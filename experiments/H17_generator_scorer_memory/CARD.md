# H17 · A memory read by both the generator and the scorer, trained with them, picks better paths

**Siddesh** · offline · ⏸ parked (negative) · 7 Nov – 12 Nov 2026 · hypothesis

[← all experiments](../../README.md#hypothesis-experiments) · [the account](README.md) · [experiment.toml](experiment.toml)

**Builds on:** [H05](../H05_ssm_memory/CARD.md), [H15](../H15_prediction_memory/CARD.md)

## Question

H05 found that the camera's past, read through a small probe, adds little; H15 carried only the planner's own outputs and could not be told from the same layer wiped. Both left the released model frozen. Does a memory help when the two parts that decide the drive, the generator that proposes 32 paths and the scorer that picks one, are trained to use it?

## Hypothesis

A memory of 16 slots, written at every moment from the frozen encoder's output and read by both the generator and the scorer, trained together with them from Drive-JEPA 0.1.8b on Physical AI AV, makes the scorer pick better paths than the same model with the memory wiped at every moment. Expected: a higher mean grade of the picked path on the picking set, and at least +0.01 on moments within 5 s after a cut-in, a crossing or a hard brake. Refuted if the carried memory does not beat the wiped one.

## Predictions

⚠️ Not pre-registered: the rule for each run was written before it started (file times and run logs agree) but in a folder outside git, so no commit date shows it

## What we learned

Camera memory has a low ceiling on this data, as far as a linear reader of pooled camera views can see. With a healthy memory (slots distinct, gates open, earlier views recalled), carrying it gave a pick grade of 0.7313 against 0.7355 with the same weights and the memory reset every moment, on 1,131 graded moments (-0.0042, 95 % interval -0.0103 to +0.0012): no gain. The first training run's gap in favour of the carried memory (0.7752 against 0.7639, interval -0.008 to +0.032) came with a collapsed memory whose 16 slots were 99.96 % alike; that the gap is not the memory working as designed is argued, and that model did lean on what the memory held (zeroed at test time: 0.7662, and the pull-away go rate 74.5 % -> 39.6 %). A linear test found the trained memory adds nothing linearly readable for predicting the driver beyond the current view and the car's own motion history. Given the true past camera view directly, a linear reader gains 1 to 2 % on speed on all moments and up to 3.9 % (2.1 to 5.5) on moments after an event, and nothing on braking or steering; by its rule written beforehand that is unclear, and no non-linear reader was shown to do better. The car's own motion history is the stronger signal, and is a separate, later experiment. Limits: one seed, one data set, open loop only; the 12-scene closed-loop check of carried against reset had not finished when this was recorded.

## Checks that decided something

- **Was the memory in the first training run working?** (10 Nov): No. At the carried arm's chosen check the 16 slots were 99.96 % alike (mean pairwise cosine 0.9996) and the gates were almost shut (mean 0.006 per slot). → fix the memory before reading anything from the gap between the arms (H17.r3, H17.r4)
- **Does the trained memory hold information that matters for driving?** (12 Nov): No, by the rule written beforehand, for a linear reader: adding the carried memory predicts the driver's next 3 s no better than adding the wiped memory on any of six targets; both controls pass. On top of the current view and the car's own history it adds -2.8 % to +0.6 %. The rule file limits this to what is linearly readable. → ask whether the true past camera view helps at all
- **Does the true past camera view help predict the driver?** (12 Nov): Unclear, by the rule written beforehand. Views from 2 s and 4 s ago add at most 1.2 to 1.3 % on speed at +3 s (bar 2 %) and 1.7 % on event moments (bar 5 %); the view from 2 s ago alone adds 3.9 % [2.1, 5.5] on event moments at +3 s, the largest gain found; the linear reader's gains on speed exclude zero; nothing on braking or steering. The small network reader gained nothing even with the true past view, so it bounds nothing. → park the camera memory; the car's own motion history is a separate experiment
- **12 scenes in closed loop, memory carried against memory reset** (12 Nov): Not finished when this was recorded: the rule was written down and the adapter proofs had started, but no scene had been driven.
